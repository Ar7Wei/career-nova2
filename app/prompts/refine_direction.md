# 任务
从事实里提炼出一个求职方向（岗位标签 + 查询组 + 逐组城市），用于招聘平台搜索。

规则：
- role（目标岗位）：从目标岗位/工作经历/技能里判断最贴切的岗位名（人话标签，如"全栈工程师"）。
  它只用于写简历（target_role）和方向标签展示，**不参与搜索**；没有明确岗位就留空。
- keywords（二维查询组）：搜索策略，**组内多词、组间 OR**。实测平台检索语义（ADR 0018）：
  平台对多词是**自适应 AND**——有交集时按 AND 算，交集不足时**静默放宽**成 OR（返回只满足
  一个词的结果），且**放宽时留哪个词与词序无关、我们控制不了**。由此推出：
  - **一个组 = 一个概念 + 一个与它大范围共现的收窄词**（组内每个词之间用空格连接，如「Vue」「前端」→ 搜"Vue 前端"）。
    **收窄词必须和概念词大量同时出现**，AND 才会生效。
    正例：`["Vue","前端"]`（Vue 岗绝大多数是前端岗，交集大）。
    反例：`["Vue","招聘专员"]`——交集极小 → 静默退化成搜 "Vue"，你以为在收窄、其实没有。
  - **同义词/变体只留最强的那个，绝不堆一组**：写 `["vue","vue3","vue.js"]` 是白费功——
    平台自带变体匹配（搜 `vue` 一次就覆盖 vue2/vue3/vue.js），堆了反而稀释。
  - **两条线都要有**：**兜底线 1 组**（纯岗位名，捞标题不写技术的岗）+ **内容线 1~2 组**（核心技术/工作内容）。
    搜技术词准但漏（标题常不写技术）、搜岗位名全但杂——互补，不是二选一。
  - **组数：2~3 组起步**（上限 6）。一上来别顶满；岗位变少、不够用了再扩。
  - keywords 与 role 是两份独立数据，内容可重复但**互不派生**——想搜某个岗位名就在 keywords 里显式加一组。
  - 正例（前端·Vue 方向，3 组）：`[["Vue","前端"], ["React","前端"], ["前端开发"]]`
  - 负例（别这样）：`[["vue","vue3","vue.js"]]`（同义变体堆一组，无用功）；
    `[["前端"],["后端"],["测试"]]`（三个不同方向并列，不是搜索策略）。
- cities（目标城市）：**城市挂在每个查询组上，与 keywords 一一对应**——给出与上面 keywords
  **等长、同序**的城市数组，`cities[i]` 是 `keywords[i]` 那组要搜的城市（2026-09-13，ADR 0019）。
  城市**逐组必填**（除下面说的"没证据"情形），只能从以下 25 个城市里选：
  北京、上海、广州、深圳、武汉、西安、杭州、南京、成都、重庆、东莞、大连、沈阳、苏州、
  昆明、长沙、合肥、宁波、郑州、天津、青岛、济南、哈尔滨、长春、福州。
  - **定位准的求职者**：从目标城市/经历里判断出一个城市，**所有组填同一个**，如
    `[["Vue","前端"], ["React","前端"], ["前端开发"]]` + `["杭州","杭州","杭州"]`。
  - **定位散的求职者**：不同组可以配不同城市（如前端投杭州、产品投上海），据此**逐组**给城市。
  - **没有证据就留空字符串**（`cities` 长度仍与 keywords 一致，如 `["杭州",""]`）——**绝不编造
    一个城市填上**。留空表示这组还没定城市，由对话里跟用户确认；不输出"成都、杭州"这种多城市串，
    也不输出这 25 城之外的城市（会被挡回）。
  - **用户说"城市不确定 / 哪座城机会多我去哪"时**：**照样留空**（`cities` 里对应位置给 `""`），
    **不要**为了凑一个城市而自己挑一座，也**不要**因此拒绝出提案。城市不定是正当状态——
    agent 会拿这份提案去问用户（base 在哪、能接受哪几座），再用 `query_market` 逐城验。
    你的职责是**如实反映"这组还没定城市"**，不是替用户拍板。
  - 同理，用户若说"这些城市都行 / 不限"，也**留空**，别合并别编造——由 agent 去 grill 出候选城。
