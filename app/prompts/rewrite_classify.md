# 判断规则

按下表选 `text` 的取值，**只选一个**：

- **content**：请求指向内容本身——措辞、量化、补充/删减某段信息、改目标岗位相关的表述等。
  例："把腾讯那段量化一下"、"教育经历补充 GPA"、"技能这块写得太空"。
- **layout**：请求指向**顺序/排布**——哪个板块放前/放后、哪个进左栏/右栏、板块顺序调整。
  例："把毕业院校提到工作经历前面"、"技能放到左栏"、"项目经历排最前"。
- **both**：请求同时涉及内容和布局。
  例："把工作经历精简一下，顺便把技能挪到左栏"。
- **none**：请求与改简历无关（闲聊/问问题）。
  例："简历怎么生成？"、"你叫什么"。

**内容（content）与布局（layout）的边界**：删掉某段信息、改措辞、量化 = content；
板块顺序调整、左右栏归属 = layout。若只是"把某段删了"这种内容增删 → content。

**「应用已确认的优化建议」清单 → content**：若请求是一份「应用以下已确认的优化建议」清单
（逐条 `[类型] 锚点：原文 → 建议改法`），这是**改内容**，判 `content`——不要被建议里的
`structure`（结构）、`fill_gap`（补缺）等**类型名**误导成 layout。它们说的是「这条建议怎么改」，
不是「改布局顺序」。

**布局调整如何表达**：改简历 JSON 里的 `layout` 数组——每项是 slot + block 两个字段，
slot 取 `header`/`left`/`right`，block 取语义块名（work/skills/…）。调顺序 = 调数组顺序，
改左右 = 改 slot 值。这是数据，不是代码。

# 输出

按下面的 schema 输出**单个合法 JSON 对象**，四个字段**都要给**，不要输出 JSON 之外的任何内容：

```
{{"text": "content|layout|both|none", "content_request": "…", "layout_request": "…"}}
```

- `text`：意图判定，取值只能是上面四个词之一，**不要写别的**。
- `content_request`：若 `text` 是 `content` 或 `both`，用一句话自然语言写出用户要改的内容方向（供后续内容改写用）；否则填空字符串 `""`。
- `layout_request`：若 `text` 是 `layout` 或 `both`，用一句话自然语言写出用户要调整的布局方向；否则填空字符串 `""`。
- 除这四个字段外**不要**输出别的内容（不要解释、不要 markdown 代码块包裹）。
