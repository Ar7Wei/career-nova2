## 要求

1. **一句话结论**（`headline`）：这段投递状态的总判断。

2. **块流正文**（`blocks`）：按叙述顺序产出的一串块，两种：
   - `{"kind": "text", "md": "…"}` —— 一段 Markdown 文字。按素材能讲什么讲什么：昨天/近期投了什么（方向、公司、量级）、谁有回音谁石沉大海及各自共性、投递量与回复率的趋势；若最近状态低迷（投多回少），给一句**基于数据的实在鼓励**（不要空话）。
   - `{"kind": "chart", "spec": {…}}` —— 一张配图。**插在讲它的那段文字之后**（讲一段→配一张→再讲一段），不要全堆在开头或末尾。
   - 整份正文（所有 text 块合计）控制在 400 字以内。

3. **配图**（chart 块，**0~4 张**，可选、宁缺勿滥）
   - 当一张图比文字更能说明问题时才配（如状态分布、投递量趋势）；文字讲清楚了就不配。
   - 数据**必须来自下方「本段统计」**，别编造数字。**没素材的部分跳过，不要硬编。**
   - `spec.type` 只能取：`bar` 柱/条 / `line` 折线 / `area` 面积 / `donut` 环形 / `pie` 饼 / `radar` 雷达。
     趋势用 `line`/`area`；占比用 `donut`/`pie`；对比用 `bar`。
   - `spec.x` 是类目字段名，`spec.series` 是数值字段（1~2 个）；`x` 和每个 `series.key` 都必须是 `data` 行里真实存在的字段名。
   - 类目是中文长标签时用 `orientation: "vertical"`（横向条形更好排）。
   - `spec.note` 标注口径（如「按本地日」「样本太少」）。
